# Reboot 2026-10-10: the session registry earns its keep

On 2026-10-10 the laptop rebooted and every live agent session died silently
(pi, dsh `web`, opencode runs). The task ledger tracks tasks, not sessions —
a stale claim is visible only at `task reap` time, and nothing records who was
alive, with how much context, at what cost.

## What the prototype did (same morning, same box)

`sessions-tracker/tools/session` (this directory, `tools/`): `register`,
`heartbeat`, `note`, `next`, `done`, `dead`, `reap`, `ls`, `show`, `brief`.
One file per session under `sessions/`, frontmatter + `## Next` + `## Log` in
the bus grammar, every line mirrored to `run/inbox/bus.log`. Design note in
`README.md`, hermes-bot bridge in `hermes-bridge.md` (watcher/reviewer lanes
only — it never pushes, posts, or reads embargoed files).

## Backfill (the proof)

Two dead pi sessions recovered from `tools/session-extract/pi.py` — an agent
that never called the CLI still lands in the registry a day late:

| session | status | task | turns | cost |
|---|---|---|---|---|
| pi-01a113e6-3fa | dead | job/perf-regression-lead | 203 | $10.57 (3.8M in, 35M cache read) |
| pi-01a11dbc-6fc | dead | - | 0 | $0 (single-ping session) |
| pi-01a123d5-358 | live | job/drupal-bench | 8+ | current session |

Raw files: `data/2026-10-10-reboot/` (host scrubbed). Bugs caught by dogfooding
before this PR: body-parse regex on heartbeat/note, bus path double-`run/`,
`HARNESS` root order — all fixed, bus mirror verified.

## Cron (installed 2026-10-10)

```
*/15 * * * * .../tools/session reap --ttl 60 >> run/sessions-tracker/cron.log 2>&1
5 2 * * *   .../tools/backfill.sh >> run/sessions-tracker/backfill.log 2>&1
```

First `reap` run: `reaped 0` (correct — the dead sessions were already marked).

## What this proves

The research path works end to end: private prototype → scrubbed topic PR with
`meta.txt` pins → public review. Next topics flow the same way; the bot drafts
from task gates + session costs, the maintainer merges.
